## Executed source and reconstruction checkpoint

`tools/acquire_landmark_lidar.py --live` acquired bounded historical USGS points for the post office and 1615 office. OCPA footprint queries returned zero features for both exact parcel IDs; this is a verified source gap, not a missing-building conclusion based solely on an absent model link. The post-office cloud contains 301,791 points (35,884 class 6); the office contains 105,060 (9,415 class 6). Original-node receipts, cloud checksums, EPSG:32617 XY and NAVD88 meter context are saved under ignored `data/heights/landmarks/`. No raw property link is promoted.

`tools/reconstruct_landmarks.py` produces a separate proposal layer with source/hash/unit guards and explicit current-unverified status. Class 6 seeds footprints; roof-plane interpretation can use separately disclosed class 1/6 observations. Parcel polygons are search masks, not building envelopes. Adjacent classified ground references, observed variation ranges, fitted/excluded roof observations, edge simplification and geometry precision changes remain in the proposal manifest. Historical LiDAR is not a current roof survey.

The official 1615 broker PDF was successfully downloaded (3,461,629 bytes with source receipt) and physical pages 3, 4 and 9 rendered and inspected locally. This resolves the earlier web-screenshot retrieval failure. The photographs show a two-storey red-brick frontage, dark pitched roof, dormers and central columned/pedimented clock entrance. Photo capture date remains unknown; pixels are not embedded as scene textures or committed. `tools/prepare_office_appearance.py` adds original approximate brick color and dark roof materials for review; windows, columns, clock and other façade details have not been modeled.

Actual 1080p Kit comparisons at `data/renders/20261028T190230Z`, `191459Z`, `193033Z` and `194100Z` exposed excessive point-noise extrusion, fragmented roof planes, invalid crossing step faces and material-subset issues. These findings drove direct whole-region plane triangulation, connected source interpretation, crossing-edge splitting and float-precision validation. Eleven focused reconstruction tests and the full 189-test suite pass. Independent QA verified source support and caught geometry defects missed by the original tests.

**Still not accepted/activated:** the latest `194100Z` office render retains visible black triangular roof seams/cuts and incomplete architectural form. Technical test success does not override this failed visual gate. The proposal remains outside the active root assembly; the prepared activation helper has not been run. Next required correction is a verified closed roof/exterior shell preserving genuine courtyard openings, then matched visual review and reference-based façade detail. Post-office appearance also needs its own rendered review before activation. No landmark ticket is closed by this checkpoint.

The subsequent topology diagnostic found 203 single-incidence shell edges and eight nonmanifold edges in the inspected office revision, despite projected roof-area agreement within approximately 0.0009 m². Thus plan-area coverage did not prove a closed 3D exterior. `tools/mesh_topology.py` now provides a separate closed-shell edge-incidence/orientation gate after coordinate welding, with four focused regressions for closed/open shells, reversed orientation, duplicated faces, disconnected face vertices and invalid inputs. It is intended for closed building meshes, not open road/ground surfaces, and does not by itself establish freedom from self-intersection or architectural accuracy. The one-square-meter source footprint gap remains an uncertain classification gap; it has not been established as a genuine courtyard. The reconstruction is being revised before another render or activation.
