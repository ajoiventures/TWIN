# City of Orlando adapter delivery and limits

Ticket #4 implementation, October 28, 2026 local time. The existing immutable active snapshot remains unchanged. `tools/city_adapter_contract.py` adds a separate read-only quality/publication contract and two usable supplemental datasets, rather than modifying the lineage-bound shared pipeline.

## Actual delivered sources

The official City ArcGIS directory was queried and cached: 131 published services. The City [GIS download page](https://www.orlando.gov/Our-Government/Records-and-Documents/Map-Library/GIS-Data-Download) and [Open Data portal](https://data.cityoforlando.net/) remain first-class catalogs. `Address_Point` actually exposes **layer 22**, not layer 0. Its bounded safe query returned 4,621 reference address features. `OrlandoLUFutureLandUse/FeatureServer/0` returned 46 planning polygons. Both use original OBJECTID/GlobalID fields, preserve original attribute/date values and request WGS84 geometry; native City XY is EPSG:2236, US survey feet. Address IDs/PIDs remain strings. Addresses do not establish parcel/building/suite identity.

The packet also profiles the current cached City snapshots: 487 street features, four neighborhood polygons, 105 zoning polygons, eight park/recreation features, 3,402 permit records and 3,590 business-license rows. Those counts describe the extraction/query definitions, not complete neighborhood or physical-asset censuses. Permit records retain their original portal row IDs; duplicate case/license numbers never collapse distinct original rows. Historical licenses do not establish current storefront tenants. Permit dates/statuses do not prove an exact building's current construction state.

One cached zoning geometry is invalid and becomes null only in this derived packet, with an explicit quality exception; the original snapshot remains untouched. Eight street, 20 address and 773 license point features are outside the configured bbox and retain an explicit context/coordinate-review flag. The license query deliberately includes neighborhood/district context beyond the bbox, so these are not automatically errors or swapped coordinates. No automatic coordinate reversal, repair or deletion occurs.

The directory has no tree-named service in this inspected bounded listing; that does not prove no City inventory exists. Unrelated municipalities' search results were excluded. `City_of_Orlando_NAVD_88_Published_Benchmarks_WFL1/FeatureServer/1` is verified metadata for **points**, not a bare-earth DEM. Its control values, vertical units and applicability need independent record review. County OCPA parcels/buildings and external USGS/NOAA/SJRWMD elevation retain their own source contracts; they are not relabeled City data.

## Interface and safeguards

Run `python tools/city_adapter_contract.py --offline` to reproduce the packet from cached requests. Without `--offline`, only missing bounded requests are fetched. `fetch_arcgis(client, source, bbox)` uses strict ID-response validation, schema checks and 50-ID batches. `fetch_socrata(client, source, where)` retains ordered source row IDs and rejects blank identities; existing pagination is 1,000 rows with a 100,000-row guard. Both reuse the existing 60-second/three-attempt client, transient-error backoff and checksummed cache receipts. Malformed ID responses are not successful empty datasets. Valid empty responses remain explicit. Incremental delta/deletion refresh is not implemented because no verified change token is supplied; bounded full refresh remains the declared behavior. Public access was observed without credentials; numeric rate limits and update frequencies remain unknown where unpublished.

`build(root, offline=False)` produces ignored `data/processed/city_adapter_contract/packet.json` and a checksum receipt. The packet contains source register, original/native and normalized CRS/units, API/metadata IDs/URLs, source dates versus retrieval/build dates, redistribution limits, field dictionaries, eight normalized tables, first five safe rows, geometry/null/exception quality and actual discovery receipts. Source-derived counts and caveats remain visible; source update values retain their original units rather than pretending to be acquisition dates.

`validate(root)` verifies the active snapshot, packet receipt and every source/cache/tool dependency before read-only display. No agency request runs in validation. Rebuild refuses a manually altered packet, backs up its previous packet/receipt and never advances the active pointer. A failed command writes `last_failure.json` while preserving the preceding good packet and active snapshot. The three focused fixture cases cover schema/service errors, malformed versus real empty ID responses, missing fields, duplicate rows, swapped/outside coordinates, invalid/null geometry, public-field projection and distinct license row identities. Actual offline reproduction and validation pass. No BOOMS input, owner/contact notes, arbitrary source fields or credentials are imported.

## True remaining #4 closure gates

This delivery advances the original adapter AC and G04, but does not close the issue's added L-01–L-07 scope. Full-neighborhood parks are being delivered separately in `tools/inventory_neighborhood_parks.py`; the current eight-row snapshot is not that census. A comprehensive government-owner classification register, dated all-owner vacancy review, parcel/area denominator reconciliation and governing FLU/zoning/overlay/PD ordinance conditions remain unresolved. Zoning public-use status is not ownership, a vacant-inventory title is not current vacancy, and FLU designation is not approval. Accepted park-site detail belongs to the separately governed civil/environment delivery. Independent acceptance must address those actual requirements before #4 closes.
